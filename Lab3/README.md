# ЛР3. Доверенная среда выполнения. Защищённое хранилище в анклаве Intel SGX

**Цель:** получение навыков технических методов защиты информации с помощью
аппаратных средств доверенной среды выполнения ЦП.

## Описание

Программный комплекс из двух частей:

- **Enclave** (доверенная часть) — анклав Intel SGX, внутри которого хранится
  таблица учётных данных и реализованы функции доступа к ней (`ecall_get_record`,
  `ecall_get_count`). Память анклава шифруется аппаратно и недоступна ОС, другим
  процессам и при снятии дампа.
- **App** (незащищённая часть) — консольное приложение, которое создаёт анклав,
  по номеру запрашивает у него запись и печатает её, после чего выгружает анклав.

Работа воспроизводит официальный пример Intel
[«Getting Started with the SGX SDK for Windows»](https://www.intel.com/content/www/us/en/developer/articles/guide/getting-started-with-sgx-sdk-for-windows.html)
с хранилищем учётных данных. Сборка и запуск — в **симуляционном режиме**
(Simulation / x64), аппаратная поддержка SGX не требуется.

### Этапы

1. **Этап 1** — незащищённое приложение: `App/App_step1_unprotected.cpp`
   (таблица и функция запроса в обычной памяти процесса).
2. **Этап 2** — перенос таблицы и функции в анклав: `Enclave/Enclave.cpp`,
   описание интерфейса в `Enclave/Enclave.edl`.
3. **Этап 3** — интеграция: `App/App.cpp` создаёт анклав и вызывает ECALL.

## Предварительные требования

| Компонент | Версия | Примечание |
|-----------|--------|------------|
| Visual Studio | Community **2019** | Intel не выпускает SGX-плагины для VS 2022 |
| Intel SGX SDK for Windows | актуальная | скачивается с сайта Intel (нужен аккаунт) |
| Плагины SGX для VS2019 | из SDK | `SEConfigureVS2019.vsix`, `SEWizardVS2019.vsix` |

После установки плагинов в VS2019 появляется тип проекта **Intel SGX Enclave
Project** и пункты контекстного меню для работы с анклавом.

## Сборка (мастер Intel SGX в Visual Studio 2019)

> Файлы `*.vcxproj`/`*.sln` и мосты `Enclave_u.*` / `Enclave_t.*` **генерируются
> мастером Intel SGX** и не хранятся в репозитории. Ниже — порядок их создания с
> подстановкой файлов из этого каталога.

1. **Проект приложения.** Создать обычный консольный проект C++ (Solution
   `SecureStorage`). Для этапа 1 использовать `App/App_step1_unprotected.cpp`.
2. **Проект анклава.** В том же Solution создать проект типа *Intel SGX Enclave
   Project*. Заменить сгенерированные файлы содержимым из `Enclave/`:
   - `Enclave.cpp` — реализация ECALL и таблица данных,
   - `Enclave.edl` — описание интерфейса (раздел `trusted`),
   - `Enclave.config.xml` — свойства анклава.
3. В оба проекта через **NuGet** подключить пакет Intel SGX SDK.
4. Выставить конфигурацию **Simulation / x64** в *Диспетчере конфигураций* (именно
   там, а не только в выпадающем списке на панели — иначе часто не применяется).
5. Собрать проект анклава → должна появиться библиотека **`Enclave.signed.dll`**.
   Если сборка требует RSA-ключ — сгенерировать его по пути из текста ошибки:
   ```bat
   openssl genrsa -out Enclave_private.pem -3 3072
   ```
6. В проекте приложения вызвать контекстное меню → **Import Enclave**, выбрать
   `Enclave.edl`. Добавятся `Enclave_u.h`/`Enclave_u.c`. Переключить проект на
   `App/App.cpp` (интегрированная версия).
7. Собрать и запустить приложение. При ошибке отсутствия `*.dll` — скопировать
   её из каталога `packages` в каталог сборки `.exe`.


### Анализ модели безопасности

С помощью hex-редактора или дизассемблера открыть `App.exe` и `Enclave.signed.dll`
и убедиться, что строки таблицы **отсутствуют в открытом виде** в коде приложения
(они внутри анклава). По условности лабораторной работы данные объявлены в коде
статически, поэтому в `Enclave.signed.dll` их фрагменты могут быть видны — в
отчёте это обсуждается (см. `theory_answers.md`, вопрос 7).

## Структура файлов

```
Lab3/
├── README.md
├── theory_answers.md
├── App/
│   ├── App_step1_unprotected.cpp   — этап 1: версия без SGX
│   └── App.cpp                     — этапы 2–3: версия с анклавом
└── Enclave/
    ├── Enclave.cpp                 — реализация ECALL + защищённая таблица
    ├── Enclave.edl                 — описание интерфейса анклава (ECALL)
    └── Enclave.config.xml          — свойства анклава
```

> `Enclave_private.pem` (ключ подписи) и автогенерируемые `Enclave_u.*`,
> `Enclave_t.*`, каталоги `packages/`, `Debug/`, `Release/`, `Simulation/` в
> репозиторий не коммитятся (см. `.gitignore`).
